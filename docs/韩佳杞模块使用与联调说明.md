# 创作工作台、成长专栏与个人资料

实现日期：2026年11月4日。基于本次读取的 bccx7/OnlyCampus main 源码快照扩展，保留现有阅读互动及审核运营功能。源码快照不含 Git 历史，尚未提交远程仓库或部署到 Azure。

## 启动与升级

需要 Node.js 22+ 和 MySQL 8。执行 `npm ci`，复制 `.env.example` 为 `.env`，填写本机数据库信息。新演示库执行 `npm run db:init`；已有库先备份，再执行 `npm run db:migrate`。不要用种子脚本升级正式数据。然后 `npm run dev`。

迁移新增 `users.avatar_path`、`series.cover_path`、`articles.created_at` 和 `articles.submitted_at`，并将正文扩为 MEDIUMTEXT，以支持最多50000字符的中文正文。继续使用已有 `articles.version`、审核记录与首次发布事件表。初始化会自动调用同一迁移；重复迁移已验证。

登录普通用户后从共享导航进入“创作中心”。现有管理员账号继续使用管理后台；管理员不能调用私人创作接口。演示账号仅限本地测试，勿用于公网。

## 页面与操作

| 路由 | 内容 |
| --- | --- |
| `/studio` | 状态数量、文章状态筛选、分页、文章管理入口 |
| `/studio/articles/new` | 新建服务器草稿 |
| `/studio/articles/:id/edit` | 保存、Markdown安全预览、提交、撤回、整改、删除、审核历史 |
| `/studio/series` | 专栏列表与新建 |
| `/studio/series/:id` | 信息、封面、公开状态、文章关联、阶段和上移下移 |
| `/series/:id` | 公开章节目录和成长时间线；视图保存在URL |
| `/me/profile` | 昵称、简介和头像 |

草稿只在点击保存时写入数据库，不自动保存，不使用浏览器本地草稿恢复。保存失败保留输入；离开有未保存内容的页面弹出可取消的确认框，关闭或刷新页面使用浏览器的离开提示。保存后显示时间。提交审核是独立操作，修改未保存时须先保存。

待审和已发布文章不能直接修改；待审与已发布可撤回，已发布撤回同时取消精选。驳回文章保存后仍为REJECTED，重提后变为PENDING。下架文章先整改为草稿，再保存、提交。只允许草稿、驳回和下架文章软删除。

专栏支持最多50篇本人未删除文章，一篇文章仅能归属一个专栏。管理页包含草稿，公开页只含已发布未删除文章；隐藏或没有公开文章的专栏返回404。删除专栏只解除关联。章节顺序和时间线分别依据 `sort_order`、`first_published_at`；同一时间按ID排序。数量与更新时间只计算公开内容。首页、作者页和正文的专栏入口已接通，正文仍不显示文章目录。

头像、文章封面和专栏封面均复用公共上传服务。上传后还需保存对应表单；未保存的上传文件不会自动绑定。此服务面向公开图片，不支持私密草稿附件。

## 接口与事务约定

新增入口统一在 `backend/creator.js`，由 `server.js` 安装，沿用登录会话及全局CSRF检查。所有私人接口要求USER角色并检查本人归属；公开查询不会返回草稿正文。

文章接口：`GET /api/studio/overview`、`GET/POST /api/studio/articles`、`GET/PATCH/DELETE /api/studio/articles/:id`，以及 `POST /api/studio/articles/:id/submit|withdraw|revise`。

PATCH保存文章发送完整编辑字段：`title`、`summary`、`bodyMarkdown`、`categoryId`、`tagIds`、`coverPath` 和 `version`。状态操作及删除也须发送 `{version}`。冲突返回409，客户端保留输入，不自动覆盖。所有文章写入锁定相同文章行，和已有审核服务共用版本递增规则。首次发布时间及首次发布事件不被作者操作重置。

专栏接口：`GET/POST /api/studio/series`，`GET/PATCH/DELETE /api/studio/series/:id`，`PUT /api/studio/series/:id/articles`，公开详情 `GET /api/series/:id`。原有作者专栏查询继续复用，首页和作者页增加仅依据公开文章计算的数量、更新时间与稳定排序。

PUT关联发送 `{articles:[{id,stage}],expectedIds:[原始文章ID]}`。关联、阶段和排序在同一事务内保存；原始集合已变化返回409。可同时发送 `name`、`description`、`coverPath`、`isPublic`，使专栏信息与关联一起原子保存，页面已采用此方式。选中文章按ID锁定，避免不同专栏并发抢占同一文章。

资料：`PATCH /api/me/profile` 发送 `{nickname,bio,avatarPath}`。保存后刷新当前显示身份；公开主页、帖子预览、详情及账号区使用真实头像。审核结果通知现在跳转本人创作详情，评论与回复通知仍定位公开评论。

跨模块修复：登录返回白名单加入创作、专栏及资料路由；无效会话清除Cookie，避免被禁用后无法正常取得新会话令牌。后端JSON限额扩大到400KB以容纳50000字符正文。
