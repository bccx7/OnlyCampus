# 赵庆浩模块使用与联调说明

本次在2026年11月3日从 GitHub 官方主分支压缩包取得的代码上接入账号管理、审核后台、站内通知和统计。保留现有注册自动登录、CSRF令牌轮换、评论回复与阅读页面。源码压缩包下载不包含提交编号，合并时请以组员当前主分支为准核对差异。

## 已实现的入口

| 入口 | 用途 |
| --- | --- |
| `/login`、`/register` | 沿用已有账号页面，增加管理员登录支持；注册仍强制普通用户 |
| `/admin` | 用户、公开文章、待审文章、可见评论概览，近7日首次发布折线图与数值表 |
| `/admin/articles` | 按状态和标题查询、正文预览、审核历史、通过、驳回、下架、精选 |
| `/admin/users` | 查看用户，禁用与恢复普通账号，记录原因 |
| `/admin/comments` | 检索评论、隐藏违规评论，不能恢复本人已删除的评论 |
| `/admin/taxonomy` | 分类及标签的新建、改名、排序、启停与未引用项删除 |
| `/me/notifications` | 通知类型和未读筛选、单条及全部已读、跳转文章与评论 |

管理界面采用独立工作台布局，公共阅读页面保留原布局。菜单控制和后端角色检查同时存在，普通用户直接请求管理接口也会被拒绝。

## 本地启动

需要 Node.js 22及以上、MySQL 8。解压后进入包含 package.json 的目录，执行 `npm ci`。复制 `.env.example` 为 `.env`，填写自己电脑的数据库信息和随机 Session 密钥。包内没有数据库密码或预设管理员。

全新本地演示数据库执行：

```powershell
npm run db:init
```

已有数据库先备份，再执行不导入演示数据的升级：

```powershell
npm run db:migrate
```

升级补充文章版本、账号会话版本、用户创建时间、分类排序、评论回复字段及审核、日志、首次发布事件表；通知关联评论改为可空。可重复执行。DDL不能整体回滚，生产发布前应在备份副本验证；只允许一个升级进程运行。历史首次发布时间按原数据库记录回填，历史数据是否准确需要组员确认。

创建专用管理员。将下面密码占位内容替换为自己设置的12—64位密码（UTF-8不超过72字节）；脚本不会覆盖已有账号，也不会提升普通账号为管理员。

```powershell
$env:ADMIN_USERNAME='campus_admin'
$env:ADMIN_PASSWORD='请替换为你自己设置的密码'
npm run admin:create
Remove-Item Env:ADMIN_PASSWORD
npm run dev
```

打开终端显示的网址。管理员登录后，从侧边导航进入管理后台。需要独立演示审核时，可在本地演示库执行 `npm run db:demo-admin`，为种子作者创建一篇待审文章；该命令禁止在 NODE_ENV=production 时运行，不重置已有文章状态。种子作者 author 和读者 reader 的密码是 campus123，仅用于本地。

## 与两位组员的接口约定

### 文章与专栏负责人

文章审核接口接受 `{action:'APPROVE'或'REJECT', reason, version}`；下架接受 `{reason, version}`。审核版本从后台详情接口读取。文章状态、审核记录、首次发布事件和作者通知在同一事务内写入；并发审核仅一个成功，另一个返回409。

当前包没有补写韩佳杞的作者工作台、文章编辑和专栏服务。作者端提交、撤回、删除、整改时必须锁定相同文章记录或使用带版本条件的更新，并递增 articles.version。已发布文章撤回时取消精选；待审核状态禁止直接编辑。前端只做按钮禁用不能代替后端校验。

通知类型为 COMMENT、REPLY、APPROVED、REJECTED、OFFLINE。审核通知没有 comment_id。已驳回和下架通知会说明原因；公开目标不可访问时通知页面显示不可用，不读取私人正文。未来作者工作台接入后，可把这类通知的跳转改为本人工作台详情。

### 阅读互动负责人

`backend/notifications.js` 导出 `notify(connection,payload)`。必须传入评论事务的同一条连接，提交或回滚由调用方负责。现有评论与回复已接入该服务；自己评论自己、回复自己不产生消息。

通知点击使用 `commentId` 查询参数与 `#comment-编号` 锚点，复用现有评论定位与展开逻辑。

`POST /api/uploads/images` 接受 multipart/form-data，文件字段名为 image，登录且携带 X-CSRF-Token。支持JPEG、PNG、WebP，最大5MB、2000万像素；服务端真实解码并转为随机命名WebP，返回 `{path:'/uploads/文件.webp'}`。此服务用于公开头像与封面，不能用于存放需要权限保护的草稿附件。

### 账号与数据库

用户禁用及恢复都会递增 session_version，旧会话即使未经禁用期间的访问，恢复后也不能再次生效。已经开始执行的请求不会被此机制撤回。所有管理操作禁止禁用管理员。注册端忽略传入角色与状态。

本版本数据库连接统一使用UTC，近7日统计换算为北京时间且缺失日期补0。旧数据若按北京时间直接保存，升级前需先确认并转换时间，不能直接假设为UTC。

## 发布前检查

生产环境执行 `npm ci`、`npm run db:migrate`、`npm run build` 后按原部署指南发布。Nginx应将 `/api/` 和 `/uploads/` 转发到后端，其他页面走SPA回退。保留 backend/uploads 目录并纳入备份；构建目录不包含上传文件。Session密钥和数据库凭据通过环境变量提供。数据库升级与代码发布要配套进行。

本模块通过 zqhao28/OnlyCampus 的 feature/zhao-admin-notifications 分支向原仓库提交PR，尚未修改Azure服务器。已有线上版本不自动包含本次改动。合并时特别检查 backend/server.js、database/init.js、frontend/src/main.js 和 frontend/src/App.vue。

## 验证与演示

测试需要一个专用测试数据库和运行中的本地后端，不应指向共享线上库。启动后运行 `node --test --test-concurrency=1`。重复执行前重启后端，以免测试登录累计触发正常的限流。

新增用例覆盖普通用户越权、并发审核、审核通知失败事务回滚、重复发布统计、通知归属、评论隐藏、账号禁用恢复后旧会话失效、管理员保护、已引用分类保护、真实与伪造图片上传。保留并更新原登录、注册、阅读互动、分页权限、Markdown和导航回归。

建议自己演示：管理员登录 → 待审文章预览 → 驳回或通过 → 作者查看通知 → 文章公开展示 → 管理员下架 → 公开文章不可用 → 分类维护 → 用户禁用 → 七日统计。截图与视频应来自自己实际运行的结果；实验报告按自己的实现、理解和测试记录填写。

## 当前限制

作者创作与专栏功能仍待另一成员接入。图表使用SVG折线图和数值表，未采用原方案提及的ECharts。通知未读数每30秒刷新，不使用实时推送。登录限流仍沿用已有的进程内实现，多实例部署需要共享限流。图片上传提供公共服务接口，头像及封面选择器由相应页面负责人接入。
